# Aceptación local de la interfaz P-02

Fecha: 2026-10-28. Rama: `feat/pro`. Contrato: [política adaptativa P-02](../../specs/p02-adaptive-policy.md).

## Alcance aceptado

- Editor integrado en los parámetros de intervenciones combinadas para habilitar `adaptive-policy-v1`, cambiar umbrales de cierre/reapertura y activar prioridad por anillo.
- Historial explicable basado en decisiones retornadas por el backend para una réplica real: estado SEIR diario, fracción infecciosa, dosis asignadas/efectivas, cierre, brigadas, anillo, saldo y motivos.
- Selector de réplica; encabezado que identifica versión y estrategia dirigida; límites educativos visibles.

## Prueba de aceptación ejecutada

Con Vite en `127.0.0.1:5174` y API local en `127.0.0.1:8000`:

1. Configuré población 50, horizonte 3 días, 2 réplicas y 2 dosis.
2. Habilité intervenciones combinadas y la variante adaptativa; dejé umbrales 5%/2% y prioridad por anillo.
3. Consulté la red con el endpoint real, abrí la comparación y ejecuté las tres estrategias.
4. Verifiqué resultados marcados como experimento real y un historial de backend para la réplica seleccionada, con cuatro filas diarias (día 0 a 3), acciones, saldo y motivos. El selector ofreció las dos réplicas.
5. El historial mostró, entre otras decisiones observadas, anillo activo el día 0 y brigadas pausadas cuando no había infecciosos en días posteriores.

La salida de esta corrida pequeña sirve para comprobar la integración de UI y contrato. No es evidencia científica ni estimación sanitaria; n=2 no habilita bootstrap. No se usó fixture para el resultado visible.

## Verificación automatizada

- La prueba frontend de extracción/mapeo de decisiones adaptativas cubre datos presentes, motivos legibles y ausencia de historial.

La brecha de editor e historial visual de P-02 queda cerrada localmente. La aceptación integral de reglas con escenarios ascendentes/descendentes y la aceptación humana de la experiencia completa permanecen asociadas a T-13..T-16 y no se infieren de esta corrida.
