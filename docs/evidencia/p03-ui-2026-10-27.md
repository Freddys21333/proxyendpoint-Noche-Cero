## 3. Integración HTTP real

Servidor: `backend/.venv/Scripts/python.exe scripts/serve_api.py` en `:8000` (habilita `LOCAL_JOBS_ENABLED=1`).

```sh
node --experimental-strip-types scripts/verify_jobs_flow.mjs
```

Resultado (trabajo de 3 réplicas, escenario 60 personas × 4 días, semilla 424242):

```json
{"status":"passed","jobId":"44dc297a-1029-43fe-8fed-214e580120ff","states":["running","completed"],"replicates":3,"experimentHash":"sha256:d3a86e4d00a9a0a6e86f838e16f6d45ae3fb839163353a77b921cda8fe0e9891","sequentialHashMatches":true,"cancelledJobId":"449a0d95-7cd3-4eb2-8d86-99a8eec79e96","idempotency":"replayed-and-conflicted","token":"unknown-token-404","partialResult":"blocked-409"}
```

Cubre: límites publicados, creación, replay idempotente, conflicto de clave, sondeo hasta `completed`, estructura del resultado, **igualdad del hash con `compare` secuencial**, token desconocido (`404`), `JOB_NOT_READY` antes y después de cancelar (`409`) y cancelación terminal.

Notas de ejecución:

- La vista previa usa el contrato síncrono (máx. 30 réplicas) aunque el trabajo admita 100; el script previsualiza con 3 y crea el lote largo con 100.
- El estado inicial puede ser `pending` o `running` porque el trabajador toma el trabajo antes de responder la creación. La primera versión del script exigía `pending` y falló una vez; ahora acepta ambos.
- Con 8 trabajos retenidos la API responde `503 COMPUTE_UNAVAILABLE`; el script crea 2 por ejecución y conviene reiniciar la API entre tandas.

## 5. Defectos encontrados y corregidos durante la aceptación

1. **Los trabajos no se restauraban al recargar.** El efecto de recuperación usaba un `ref` de «una sola vez» junto con un flag `cancelled`; en React StrictMode el cleanup de la primera ejecución cancelaba la única carga y la segunda salía por el `ref`. Se eliminó el `ref`; ahora cada montaje recupera del servidor y el aviso de trabajos perdidos se muestra aunque no se recupere ninguno.
2. **Avisos ilegibles en Noche Cero.** El tema global pinta `p`/`strong` con color claro y el aviso conserva fondo claro; el texto quedaba casi invisible. Se fuerza `color: inherit` con especificidad suficiente dentro de `.pro-workspace`.
3. **Metadatos y enlaces invisibles.** `dd`, `dt`, `li` y `.pro-link-button` conservaban colores del tema claro sobre tarjetas oscuras. Se añadieron anulaciones explícitas para Noche Cero.

## 6. Límites y pendientes

- Todo es **local**: sin AWS, sin URL pública y sin gasto.
- La cola es en memoria: reiniciar la API invalida los tokens de la sesión; la UI lo avisa, pero no puede recuperar esos trabajos.
- El camino «resultado incompleto» (réplicas fallidas) está cubierto por pruebas unitarias; forzarlo en navegador requeriría inyectar un fallo en el motor y no se hizo.
- El trabajo reutiliza la **vista previa vigente**; no hay todavía una pantalla que persista trabajos entre pestañas o usuarios.
- La pantalla de jobs no sustituye la aceptación humana T-13..T-16 ni el gate científico T-22, que sigue **INCOMPLETO**.
