# P-03: integración local de trabajos en la interfaz

Fecha: 2026-10-28. Entorno: navegador local `http://127.0.0.1:5174/` y backend local con `LOCAL_JOBS_ENABLED=1`. Sin AWS ni credenciales externas.

## Cambio

- La vista PRO crea trabajos reales con `POST /v1/jobs`, consulta progreso y estados, cancela y recupera el resultado completo con el cliente de API existente.
- La red se obtiene mediante preview del backend. Si el lote excede el máximo síncrono, el preview usa como máximo el número de réplicas por defecto del servidor para obtener el mismo `graphHash`; el request de jobs conserva todas las réplicas pedidas. Esto permite R=31 sin elevar el límite síncrono de 30.
- La cantidad máxima y concurrencia se leen de `jobLimits`; no se reutiliza el fixture de 1.000. El historial y el token/capacidad viven en `sessionStorage` de la pestaña. Al recargar, la UI consulta de nuevo el estado. El token no se escribe en logs ni se incluye en exportaciones.
- El polling aumenta su intervalo hasta 15 s, aborta al cambiar de trabajo o desmontar la vista y solo muestra la tabla/ZIP tras recuperar un agregado completo. El ZIP se genera desde el `CompareResponse` validado.
- La pantalla no muestra fixtures como jobs reales. Señala que las simulaciones son ficticias y locales, y que AWS no está desplegado.
